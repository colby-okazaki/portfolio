Group Restaurant Matcher

For a group of friends who can't agree on where to eat. Everyone swipes yes or no on nearby restaurants, and the app shows a match when the whole group likes the same place. I built the back end.

How it works

  1. One person starts a group and picks a location and filters: distance, price and type of food.
  2. They share a 4-digit code, and everyone who joins sees the same stack of restaurant cards.
  3. Each person swipes yes or no on their own phone.
  4. As soon as everyone says yes to the same place, every phone gets the match, with the address, hours and a button for directions.

How it's built

  • My part. Groups, restaurant data, swipes, match logic and live updates. The front-end developer and I designed the REST API together and both build against one written contract.
  • Live on Render. The app and the server are both online. With two players, the match arrives about 0.2 seconds after the last swipe.
  • Live updates. Socket.io tells every phone when someone joins and when there's a match or no match. Phones that drop off catch up when they reconnect.
  • Safe to retry. Sending the same swipe twice doesn't count twice, so a flaky connection can't break a group's result.
  • Real restaurants. Places come from OpenStreetMap, which is free and needs no key: 20 places in about 1.4 seconds when tried live. A place search turns a typed location into coordinates.
  • More than yes or no. The host sets the filters and starts the round. Players can nudge someone who's slow (once a minute), end a round early and see the closest picks, or take a quick vote after a no-match. A new round can start in the same group, and if the host leaves, the role passes on.
  • Protection. Joining and creating groups are rate limited, and old groups are cleaned up.
  • Tested. The load test numbers above come from a script in the repo, so they can be re-run, and 64 automated tests cover the back end.
  • Next. Open groups are already saved every few seconds and restored on restart. The next step is connecting the live server to a PostgreSQL database so groups survive the free server going to sleep, then testing with a real group at dinner.
