Collaborative Whiteboard

Draw with other people on one canvas, live. Each board has its own link, is saved to a database, and can be served by several server instances at once.

Code →

What it does

  • Drawing. A freehand pen, an eraser and a colour picker, with strokes appearing for everyone as they're drawn. It works with a finger on phones and tablets.
  • Sticky notes. Add, edit and move notes. While someone is editing a note, others see it outlined with that person's name.
  • Live cursors. You can see where everyone else is pointing.
  • Boards. Each board has a shareable link, and anyone joining mid-session gets the full board first.
  • Undo and redo. Step back through your last 50 strokes, and only your own.
  • Export. Download the board as a PNG at twice the screen resolution.

How it's built

  • Less traffic. Stroke points are batched about every 40ms, and cursors update at most every 50ms but always land on the final position.
  • Two people, one note. Dragging or editing a note takes a lock on the server, which expires after 60 seconds so a crash can't leave a note stuck. Each save also carries the version it was based on, and the server rejects it if the note has changed since, so nobody's work is silently overwritten.
  • Saving. Live state stays in memory or Redis so drawing never waits on the database. Changes are written to PostgreSQL in the background, with a version check so a delayed older write can't replace a newer one.
  • Several servers. With Redis, any number of server instances can serve the same board, and drawing, cursors, notes and locks sync between them.
  • The server doesn't trust clients. Every message is validated before it touches the store, and each connection has its own rate limit, so one client flooding the server doesn't slow anyone else.
  • Deploys don't lose work. On shutdown the server saves half-drawn strokes and waits for queued database writes before exiting.
  • Tested. GitHub Actions runs the unit, component and integration tests on every push against real PostgreSQL and Redis, and checks that the Docker image starts and stops cleanly.
